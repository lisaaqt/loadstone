# Configuration

## Panel and worker

Set these in `.env` next to `registry-deploy/docker-compose.yml` (or directly in the all-in-one file). The panel and the worker use the same values.

| Variable | Default | Description |
| --- | --- | --- |
| `APP_URL` | required | URL people open in the browser. Use `https://` behind a reverse proxy (enables secure cookies). |
| `APP_SECRET` | required | 32+ random characters. Encrypts node tokens and stored passwords — never change it after the first start. |
| `POSTGRES_PASSWORD` | required | Password of the bundled PostgreSQL database — never change it after the first start. |
| `APP_PORT` | `3000` | Host port the panel is published on. |
| `ALLOWED_ORIGINS` | — | Extra origins allowed to send requests (comma-separated). Usually empty. |
| `TRUST_PROXY` | `false` | Set to `true` only behind a reverse proxy that sets `X-Forwarded-For`. |
| `LOADSTONE_REGISTRY` | `lisaaqt` | Docker Hub namespace (or `registry.example.com/team`) the images are pulled from. |
| `LOADSTONE_VERSION` | `latest` | Image tag, e.g. `0.2.4` to pin a version. |
| `COMPOSE_PROFILES` | `db-backup` | Optional services: `db-backup` writes daily database dumps to `./backups`. |
| `DB_BACKUP_INTERVAL_SECONDS` | `86400` | Seconds between database dumps. |
| `DB_BACKUP_KEEP` | `7` | Number of database dumps to keep. |
| `USER_SERVER_LIMIT` | `0` | How many servers a normal user may create themselves (`0` = only admins create servers). |
| `USER_SERVER_MAX_MEMORY_MB` | `4096` | Most RAM per self-created server. |
| `USER_SERVER_MAX_DISK_MB` | `20480` | Most disk per self-created server. |
| `USER_SERVER_MAX_CPU_PERCENT` | `200` | Most CPU per self-created server (100 = one core). |
| `UPDATE_CHECK` | `true` | Warn admins when the registry has a newer version. |
| `UPDATE_REGISTRY_USERNAME` / `UPDATE_REGISTRY_PASSWORD` | — | Read-only registry login for the update check, only needed for private repositories. |

SMTP (email), backup storage (S3 / SFTP), database hosts and the panel name are configured in the panel under **Settings**.

## Agent

Set these on the agent container on each node. The panel shows a ready-to-run command under **Nodes → Add node**.

| Variable | Default | Description |
| --- | --- | --- |
| `LOADSTONE_TOKEN` | required | Token generated by the panel (≥ 32 characters). |
| `LOADSTONE_PORT` | `8080` | Listen port. |
| `LOADSTONE_HOST` | `0.0.0.0` | Listen address. |
| `LOADSTONE_DATA_DIR` | `/var/lib/loadstone` | Server files, local backups and metadata. |
| `LOADSTONE_HOST_DATA_DIR` | = data dir | Host path of the data dir if it differs from the path inside the container. |
| `LOADSTONE_TLS_CERT` / `LOADSTONE_TLS_KEY` | — | Serve HTTPS/WSS directly. |
| `LOADSTONE_MAX_UPLOAD_MB` | `4096` | Maximum single upload size. |
| `LOADSTONE_PREPULL` | `recommended` | Server images downloaded in the background: `recommended`, `all`, `none` or a comma-separated list. |
| `DOCKER_HUB_USERNAME` / `DOCKER_HUB_TOKEN` | — | Optional Docker Hub login for pulling server images (raises the rate limit). |
| `DOCKER_HOST` | socket | Docker Engine endpoint. |

> The agent creates bind mounts for server containers, so `LOADSTONE_DATA_DIR` must be mounted at the same path inside the agent container as on the host.

Keep the agent port reachable only by the panel (firewall, private network, WireGuard/Tailscale or TLS). Access to the Docker socket is equivalent to root on that host.

## Notes and limits

- Storage quotas are **soft**: the agent enforces them on uploads, edits, extraction and plugin installs, but the server process itself can still exceed them.
- Container memory is the configured heap plus about 20 % overhead (at least 384 MB).
- Configuration changes take effect on the next start or restart.
